# AI Agent Pro — 与主流 Agent 全面差距剖析与超越路线（完整版）

> 版本：v1.0 ｜ 基于 2026-07-25 代码实测（非凭记忆）
> 覆盖两大块：① 六维（性能/功能/操作/兼容性/拓展性/全技术栈）对比主流 Agent 差距总表；② 内容搜索/爬虫专项差距；③ 全部问题统一清单与 P0/P1/P2 路线。
> 说明：本文件为新增分析文档，不修改任何业务代码。

## 0. 文档目的

把「本产品相对 KIMI / 通义 / Coze / Manus / Qoderwork 等主流 Agent 还差什么」做一次**完整、可量化、带代码依据**的总结，并将此前分散的「六维分析」与「内容搜索/爬虫分析」合并为一份总文档，便于后续按图施工。

**一句话结论**：产品在「本地知识检索（BM25+向量+RRF）」与「桌面端一体化体验」上已具备优势；最大短板集中在**数据获取深度（网页抓取/爬虫）**与**架构自洽性（双后端割裂、引擎未内置、跨平台数据路径写死）**两条线上。补齐这些，即可在「全技术栈可用性」维度反超多数只做聊天壳的竞品。

## 1. 六维对比主流 Agent 差距总表（核心）

### 1.1 六维定义

| 维度 | 含义 |
|------|------|
| **性能** | 启动速度、资源占用、并发与缓存、渲染/解析效率 |
| **功能** | 联网搜索、网页抓取、研究编排、多模态、工具丰富度 |
| **操作** | UI/UX、可中断/可续、失败引导、人机协作流畅度 |
| **兼容性** | 跨平台一致性、部署分发、网络边界、安全模型 |
| **拓展性** | 插件/模块机制、Provider 可插拔、第三方接入门槛 |
| **全技术栈** | 前端→后端→模型→工具→数据→部署 全链路的完整度与自洽性 |

### 1.2 评分总表（5=领先/完备，4=可用较好，3=基础可用，2=明显缺陷，1=缺失）

| 维度 | 本产品 | KIMI/通义 | Coze/扣子 | Manus 类 | 判定 |
|------|:----:|:----:|:----:|:----:|------|
| 性能 | 3 | 4 | 4 | 3 | 持平略落后 |
| 功能 | 3 | 4.5 | 4 | 5 | **落后（爬虫/研究深度差）** |
| 操作 | 4 | 3.5 | 4 | 3.5 | **领先（桌面一体化）** |
| 兼容性 | 2.5 | 4 | 4 | 3.5 | **落后（双后端/路径写死）** |
| 拓展性 | 3.5 | 3.5 | 5 | 4 | 持平（缺插件 SDK） |
| 全技术栈 | 3 | 4 | 4 | 4.5 | 落后（链路不自洽） |

| **桌面一体化** | 4.5 | 2 | 2 | 2 | **领先** |

### 1.3 逐维剖析

#### 维度一：性能
- **现状**：Electron 42 + 渲染进程通过 `eval` 执行模块代码（`core-v10.js:18` 注释明确），无前端打包/Tree-shaking；双后端（3847 主 + 8080 搜索代理）独立进程；Playwright 懒加载（首次启动 Chromium 约 1~2s）。165 项测试通过，基础稳定性好。
- **差距**：模块以 `eval` 方式运行，解析与冷启动有开销；搜索代理独立进程增加资源与启动耦合；Playwright 未随包分发，首次使用需用户自行 `npm install playwright`，体验割裂。
- **补法**：① 引入构建期打包（Vite/esbuild）替代运行时 eval，缩小体积、提升启动；② 把 8080 搜索能力收敛进主后端 3847，消除双后端；③ Playwright 作为可选依赖随包分发或提供一键安装。

#### 维度二：功能
- **现状**：联网搜索（免费引擎依赖 8080 代理，付费博查/Tavily 直连）、深度研究编排（5 阶段）、本地知识混合检索（BM25+向量+RRF，较强）、Playwright 浏览器引擎（已写好但未接入管线）、语音/图片/文档（依赖 tesseract/pdf-parse 等但未深度融入研究）。
- **差距**：**网页抓取无 JS 渲染、无链接跟随/递归爬取、无 rerank/时效过滤、无网页监控**——这是与 Manus 类产品的核心功能差距（详见第 2 章）。
- **补法**：见第 2 章 P0/P1/P2。

#### 维度三：操作（UX）
- **现状**：桌面端一体化体验好，右侧「任务监控」栏、可折叠文件任务栏、聊天气泡圆角等已完成；deep-research 有进度回调；搜索失败有友好提示。
- **差距**：研究过程不可中途干预/续跑；搜索代理失效时虽有提示但无一键自愈；抓取失败在深度研究里未显式呈现。
- **补法**：研究任务支持中断/续跑；抓取失败可视化 + 一键浏览器重试（P0-3）。

#### 维度四：兼容性
- **现状**：`contextIsolation:true + nodeIntegration:false`（安全模型到位）；`package.json` 已配 win/mac/linux/arm 多目标构建；`BIND_HOST` 默认 127.0.0.1（安全封闭）。
- **差距**：① **双后端端口割裂**（8080 搜索代理不随主程序启动，开箱搜索脆弱）；② **Playwright 未内置**，跨平台包缺浏览器引擎，功能在不同 OS 表现不一致；③ **数据目录写死 `E:\my-ai-data`**（`main.js:62`，非 Windows 直接失效，仅回退 userData）；④ 局域网/移动端需手动设环境变量才开放，协作门槛高。
- **补法**：统一单后端；Playwright 可选随包；数据目录改用跨平台 `app.getPath` 规范；提供 UI 开关开放局域网。

#### 维度五：拓展性
- **现状**：`core-v10.js` 已有 `pluginManager` + 每用户 `plugins` 目录 + `disabledPlugins` 配置；`modules/` 目录化模块 + 依赖排序加载器；query-rewriter / task-queue / file-checkpoint 等能力已模块化。
- **差距**：插件开发无 SDK/文档，第三方拓展门槛高；搜索/研究管线未抽象为可插拔 Provider，新增数据源要改核心；抓取能力未服务化，难以被插件复用。
- **补法**：① 发布插件 SDK + 模板；② 将搜索/数据源抽象为 Provider 接口；③ 抽 `CrawlService` 供插件调用。

#### 维度六：全技术栈
- **现状**：前端（Electron 渲染 + React 局部）、后端（Express + WebSocket + better-sqlite3）、模型层（多供应商云端 API + Ollama/SiliconFlow 嵌入兜底）、工具（bash/文件/浏览器/搜索）、数据（SQLite + 文件）、部署（electron-builder 多平台）。
- **差距**：① 前端以 `eval` 运行模块，非标准构建，同构/复用弱；② 推理无完整本地闭环（聊天仍走云端，仅嵌入本地）；③ 缺统一的「工具/数据源注册表」，各能力孤岛。
- **补法**：构建期打包；推理层增加本地模型兜底（如 Ollama 聊天）；统一能力注册表（Capability Registry）。

## 2. 内容搜索 / 爬虫 专项差距

### 2.1 服务拓扑：两个后端
| 端口 | 进程 | 职责 | 实现搜索？ |
|------|------|------|-----------|
| **3847** | `server/index.js`（Node） | WS 通信、DB、知识库、记忆、路由、静态 | ❌ 无 `/api/search` |
| **8080**（默认） | 独立搜索代理 | 对接 DDG/Bing/SearXNG/博查/Tavily | ✅ 有 `/api/search`、`/health` |

> 主后端 `server/index.js:167-176` 只暴露 `/health`、`/api/models`、静态文件——**根本没有搜索接口**。免费引擎搜索全靠独立 8080 代理，代理没起就废（即此前「8080 连接拒绝」）。

### 2.2 搜索链路（`modules/search.js`）
- 主入口 `webSearch()`（line 50）：优先后端代理，失败降级 `webSearchDirect()`。
- 免费引擎 DuckDuckGo/Bing/SearXNG 在 `webSearchDirect` 里**仍走后端代理**（line 339-345），非真直连；仅博查/Tavily（需 Key）真直连。

### 2.3 深度研究抓取链路（`modules/deep-research.js` + `modules/tools.js`）
- `_fetchPage()`（line 314-326）本质调 `read_url`。
- `read_url`（`tools.js:787-867`）：裸 `http.get` + 正则，500KB 上限，默认回 5K，**无 JS 渲染**。
- 再两层截断：deep-research 留 6000（line 287），喂 LLM 仅 3000（line 337）。

### 2.4 浏览器引擎（`modules/browser-pro.js`）—— 闲置宝藏
- 完整 Playwright 封装（navigate/screenshot/click/type/extract/waitFor/evaluate/多标签），`extract()` 能拿 `document.body.innerText`（JS 渲染整页）。
- 仅通过 `/browser` 命令暴露（line 219-250），**未被搜索/研究调用**。

### 2.5 知识库（`modules/knowledge.js`）—— 亮点
- BM25 + Ollama 嵌入 + SiliconFlow 云端兜底 + RRF 融合；无嵌入时自动降级 BM25。同体量产品中上乘。

### 2.6 爬虫「七宗罪」
1. 搜索强依赖「非自带」独立 8080 代理，代理挂则免费搜索全废。
2. 页面抓取无 JS 渲染，SPA/动态内容抓不到。
3. 单页容量与截断过激（500KB 下载 / 默认 5K 回传 / 研究侧砍到 3K 喂 LLM）。
4. 无链接跟随 / sitemap / 递归爬取，只能抓给定 URL。
5. 无 rerank / 时效过滤 / 去重 / 权威性评估。
6. 无网页监控 / 增量抓取。
7. Playwright 工业级引擎已写好却闲置未接入。

## 4. 超越路线（P0 / P1 / P2 合并）

### P0 — 立竿见影（1~2 天，低风险）
- **P0-1｜Playwright 接入深度研究抓取**：`_fetchPage()` 优先 `Core.browserPro.extract()`（JS 渲染整页），失败回退 `read_url`。消除 P-02、激活 P-05。
- **P0-2｜搜索降级增强**：8080 不可用时自动切博查/Tavily 直连（已配置 Key），无 Key 给清晰引导；搜索结果本地 TTL 缓存（10 分钟），缓解 P-01。
- **P0-3｜抓取失败可视化 + 一键重试**：deep-research 进度标注跳过页，支持浏览器引擎重试（P-04）。
- **P0-4｜放宽单页截断**：研究侧保留上限由 3K/6K 提升至 8K~15K（配合 P0-1 渲染文本质量），缓解 P-03。

### P1 — 体系成型（1~2 周，中等风险）
- **P1-1｜递归爬取 `CrawlService`**：带最大深度/页数/域名白名单/去重预算，从种子 URL 自动扩展（P-06）。
- **P1-2｜爬回内容进知识库**：复用 BM25+向量+ RRF 做二次检索（P-06 配套）。
- **P1-3｜rerank + 时效过滤 + 权威性评分**（P-07）。
- **P1-4｜统一单后端**：把 8080 搜索能力并入 3847，消除双后端割裂（P-09）。
- **P1-5｜Playwright 随包/一键装**，跨平台一致（P-10）。
- **P1-6｜数据目录跨平台化**：改用 `app.getPath` 规范（P-11）。
- **P1-7｜前端构建期打包**：Vite/esbuild 替代 eval，提性能（P-13）。
- **P1-8｜插件 SDK + Provider 抽象**：搜索/数据源可插拔（P-14、P-15）。

### P2 — 全面领先（月度，较高投入）
- **P2-1｜网页监控 / 增量 / 变更告警**（P-08，复用 SQLite/任务队列）。
- **P2-2｜UI 开关开放局域网/移动端**（P-12）。
- **P2-3｜统一能力注册表 Capability Registry**（P-16）。
- **P2-4｜推理本地闭环兜底**（P-17）。
- **P2-5｜研究任务可中断/续跑**（P-18）。
- **P2-6｜多模态内容提取**融入研究（PDF/表格/OCR）。

## 5. 验收标准（可量化）

| 项目 | 验收口径 |
|------|----------|
| P0-1 | 对 3 个 SPA/动态站，deep-research 抓取正文量 ≥ 原方案 2 倍 |
| P0-2 | 8080 关闭时，已配置付费 Key 用户仍可搜索；无 Key 给明确引导 |

| P1-6 | 在 Windows/macOS/Linux 下数据目录均按平台规范自动定位 |
| P1-8 | 新增一个搜索 Provider 无需改核心代码 |
| P2-1 | 配置监控 URL 后，内容变更能在下个周期被检测并通知 |

## 6. 风险与权衡

- **Playwright 体积/启动**：Chromium 较大，建议懒加载 + 单例复用，低端机提供「仅静态抓取」开关。
- **递归爬取合规**：需尊重 robots.txt、速率限制、域名白名单，规避封禁与合规风险。
- **双后端收敛**：P1-4 是架构级改动，建议先在独立分支跑通 165 项测试再合入。
- **eval→打包**：构建期打包会改变模块加载方式，需同步迁移 preload 桥接与插件加载。
